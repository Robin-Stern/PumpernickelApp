Erstelle die Datei `evals/PROMPT-TESTING-EXPLAINED.md` mit exakt 9 H2-Sections in dieser Reihenfolge:

1. `## Warum überhaupt Prompt-Testing?` — Probabilistische Outputs vs. deterministische Tests. Analogie zu Unit-Tests: gleicher Input -> akzeptable Output-Form, nicht identischer String. Begründung warum „funktioniert in meinem Test-Chat" kein Beweis ist.

2. `## Die Architektur` — Single source of truth. App liest `shared/src/commonMain/resources/workout-system-prompt.md`. Eval liest dieselbe Datei via `prepare.mjs`, das die promptfoo-JSON-Templates regeneriert. Es gibt keinen zweiten, divergierenden Prompt. ASCII-Diagramm in einem fenced code-block (mit Unicode-Box-Drawing oder ASCII), das den Datenfluss zeigt:
   `shared/.../workout-system-prompt.md` -> `prepare.mjs` -> `evals/prompts/workout-system.json` -> promptfoo run -> validator -> pass/fail
   Parallel: dieselbe `.md` -> App-Bundle -> Runtime.

3. `## Anatomie eines Eval-Runs` — Drei Zutaten:
   - Prompt-Template (`evals/prompts/workout-system.json` — minimaler Auszug, zeige nur das `{{variable}}`-Substitutions-Pattern)
   - Test-Cases (`evals/cases/workout.json` — ein Case mit `vars`, kurz)
   - Validator (`evals/cases/workout-validator.cjs` — nur Signatur, Details in Section 4)
   Danach zweites ASCII-Diagramm: `Test-Case vars -> Substitution -> API-Call -> Modell-Antwort -> Validator -> {pass, fail+reason}`.
   WICHTIG: Lies die echten Dateien (`evals/prompts/workout-system.json`, `evals/cases/workout.json`, `evals/cases/workout-validator.cjs`) und nimm reale Snippets — erfinde keinen Code. Snippets dürfen gekürzt sein (`// ...`), aber müssen syntaktisch dem Original entsprechen.

4. `## Validator-Pattern: Code statt LLM-as-Judge` — Zwei Optionen:
   (a) LLM-as-Judge: ein zweites Modell bewertet die Antwort.
   (b) Deterministischer Code-Validator: prüft Schema/Felder/Constraints in JavaScript.
   Wir nutzen (b). Begründung: schnell, gratis, deterministisch, reproduzierbar, kein zweites Modell als Risiko. Zeige einen Auszug aus `evals/cases/workout-validator.cjs` der zeigt, *was* genau gecheckt wird (JSON-Parse, Schema-Felder, Werte-Plausibilität). Pointe: Der Validator codifiziert exakt das Akzeptanzkriterium, das die App zur Runtime sowieso prüfen muss — Test und Production teilen die Definition von „gültig".

5. `## Der Iteration-Loop` — Hypothese -> Edit (Prompt oder Modell-Wahl) -> Eval-Run -> Diagnose (welcher Case failt, mit welchem Grund) -> Decision (commit, revert, weiter messen). ASCII-Diagramm des Loops in fenced code-block. Wer macht was: Mensch formuliert Hypothese und entscheidet, Code (validator + runner) misst, LLM produziert Output. Stelle klar: Kein Schritt im Loop ist „LLM bewertet sich selbst".

6. `## Die vier Failure-Modes die wir gefunden haben` — A/B/C/D aus `evals/MULTI-MODEL-RESULTS.md`:
   - **A: Reasoning-Trace-Token-Starvation** — `gpt-oss-20b` und `gpt-oss-120b` bei Recipe. Was passiert: das Modell verbraucht das Token-Budget im internen Reasoning-Trace, bevor es das JSON ausgibt. Output wird abgeschnitten / leer. Validator catched: JSON-Parse schlägt fehl oder Pflichtfelder fehlen.
   - **B: Schema-Shape-Inkonsistenz** — `gpt-oss-120b` bei Workout. Was passiert: das Modell liefert JSON, aber mit abweichender Verschachtelung/Feldnamen. Validator catched: Schema-Check schlägt fehl mit konkretem Pfad.
   - **C: Mode-Collapse** — `Qwen3-235B` bei Recipe. Was passiert: das Modell gibt für unterschiedliche Inputs sehr ähnliche oder generische Ausgaben zurück. Validator catched: Plausibilitäts-/Variabilitäts-Checks oder fehlende inputspezifische Felder.
   - **D: Macro-Arithmetik-Schwäche** — `Llama-3.3` bei Recipe. Was passiert: Makro-Nährwerte addieren sich nicht plausibel zur Kalorienanzahl. Validator catched: Arithmetik-Toleranz-Check.
   Pro Failure-Mode: 2-4 Sätze + ein kurzer Output-Snippet oder Validator-Fehlermeldung als Illustration. Zahlen (z. B. wie oft welches Modell fiel) aus MULTI-MODEL-RESULTS.md übernehmen. Llama-4-Maverick-503 darf erwähnt werden als „Together-Tier-Outage, Ursache unbekannt".
