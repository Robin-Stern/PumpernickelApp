Drei redundante Workout-End-Buttons auf EINEN kontextsensitiven Button reduzieren — iOS und Android funktionsgleich.

**Vor**: 3 Pfade → unklar welcher was tut
- Leading X-Button → confirmationDialog "Abandon Workout?" (3 Optionen: Save & Exit / Discard / Cancel) — KEIN Budget-Check, KEIN Penalty-Check
- Menü "Finish Workout" → enterReview() direkt — auch ohne All-Done-Check
- Menü "Workout beenden" → manueller All-Done-Check; sonst INLINE Penalty/Budget-Arithmetik + EarlyExitConfirmDialog

**Nach**: 1 Pfad → eindeutige Semantik
- Trailing-Button "Workout beenden" (Icon: `checkmark.circle` iOS / `Icons.Default.Check` Android)
- Click: allDone → `viewModel.enterReview()` direkt; sonst → EarlyExitConfirmDialog mit aktuellem `earlyExitBudget`-Snapshot; Confirm im Dialog → `viewModel.requestEarlyExit()`

**Wichtig**: `requestEarlyExit()` ist selbst-orchestrierend (siehe `WorkoutSessionViewModel.kt:1104-1120`):
- `allSetsDone` → ruft intern `enterReview()`, gibt `NormalReview` zurück
- `budget >= 1` → konsumiert Early Exit, ruft `saveCurrentAsCompletedWithoutPenalty`, gibt `Processing` zurück
- `budget == 0` → ruft `handleGeofenceExitGraceExpired` (Penalty-Pfad), gibt `Processing` zurück

Das heisst: der UI-Confirm-Dialog ist die EINZIGE Gate vor Penalty/Budget-Verbrauch. Bei `allDone` darf der Dialog NICHT erscheinen — deshalb der manuelle `allDone`-Check VOR Dialog-Open.

Purpose: Klare, eindeutige Workout-End-UX. Eliminiert die duplizierte Inline-Penalty-Arithmetik aus der iOS-View. Entfernt den verwirrenden "Abandon Workout?"-Dialog (Save&Exit/Discard/Cancel) und das doppelte "Finish Workout" / "Workout beenden" im Menü.
