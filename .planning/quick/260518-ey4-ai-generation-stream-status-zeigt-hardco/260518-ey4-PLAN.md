<objective>
Behebe den hardcoded-"5-Übungen"-Bug während des AI-Workout-Streamings.

**Root Cause (verifiziert per Code-Read):**
`WorkoutAiViewModel.kt` Zeile 113 setzt beim Wechsel in den Generating-State einen hardcoded `skeletonRowCount = 5`:

```kotlin
is AiGenerationState.Generating -> {
    if (genState.type == AiType.WORKOUT) {
        _uiState.value = WorkoutAiUiState.Generating(skeletonRowCount = 5)  // ← BUG
    }
}
```

Sowohl iOS (`AIWorkoutGenView.swift` Zeile 50, 272) als auch Android (`AiWorkoutGenScreen.kt` Zeile 115-116) lesen `state.skeletonRowCount` aus dem geteilten VM und zeigen ihn im Status-Text ("X Übungen") + im Skeleton-Loader. Beide Plattformen sind betroffen — Fix im commonMain VM behebt beides automatisch.

`AiGenerationState.Generating(type, originatingData)` enthält bereits das `WorkoutAiForm` als `originatingData`, also ist `form.exerciseCount` direkt verfügbar (siehe `AiGenerationManager.kt` Zeile 44 — Form wird beim Start übergeben).

Purpose: UI-Wahrheit. User stellt 2 Übungen ein → UI darf nicht "5" lügen.
Output: Single-line fix im shared ViewModel + manuelle Cross-Platform-Verifikation.
</objective>

**Lokalisierung:** `shared/src/commonMain/kotlin/com/pumpernickel/presentation/ai/WorkoutAiViewModel.kt`, Zeile ~111-114.

**Vorher (Bug):**
```kotlin
is AiGenerationState.Generating -> {
    if (genState.type == AiType.WORKOUT) {
        _uiState.value = WorkoutAiUiState.Generating(skeletonRowCount = 5)
    }
}
```

**Nachher (Fix):**
```kotlin
is AiGenerationState.Generating -> {
    if (genState.type == AiType.WORKOUT) {
        val requestedCount = (genState.originatingData as? WorkoutAiForm)?.exerciseCount ?: 5
        _uiState.value = WorkoutAiUiState.Generating(skeletonRowCount = requestedCount)
    }
}
```

**Hinweise:**
- `WorkoutAiForm` ist im selben Package bzw. wird bereits in Zeilen 119, 122-123 dieser Datei referenziert — Import existiert schon (siehe `genState.originatingData as? WorkoutAiForm` analog zum Success-Pfad in Zeile 119).
- Der `?: 5` Fallback ist defensiv: Wenn `originatingData` aus irgendeinem Grund kein `WorkoutAiForm` ist, behalten wir das alte Verhalten (5) statt eine 0 oder einen Crash zu produzieren. Real ist das aber nicht erreichbar — `AiGenerationManager.startWorkoutGeneration` übergibt immer ein `WorkoutAiForm`.
- Keine weiteren Änderungen nötig: iOS und Android lesen beide `state.skeletonRowCount` direkt — kein platform-spezifischer Eingriff.
- KEINE Refactorings, KEIN Umbau der State-Klassen, KEINE neuen Felder. Single-line semantic fix.

**Was NICHT tun:**
- KEIN neues Feld `requestedExerciseCount` zur State-Klasse hinzufügen — `skeletonRowCount` ist semantisch bereits "wie viele Übungen werden generiert", wir füllen es nur korrekt.
- KEIN Default-Wert in der `Generating`-Datenklasse hardcoden.
- KEIN Sync-Mechanismus zwischen Form und Generating — die einzige Schreibstelle ist diese Observer-Branch.
