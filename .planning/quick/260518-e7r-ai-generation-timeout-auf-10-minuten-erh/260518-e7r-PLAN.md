<background>
Ktor's HttpTimeout plugin gives a coroutine-level cancel. The platform engine (Darwin URLSession on iOS, OkHttp on Android) has its own socket-level timeouts. The smaller of the two cancels the request. The per-request `timeout {}` block inside OpenAICompatibleClient further overrides the engine-level Ktor config for that single call.

Current effective ceilings:
- iOS: min(Ktor 180s engine, NSURLSession 180s req / 300s resource, per-request 300s Ktor) = **180s** -- well under 5 min, matches user report
- Android: min(Ktor 300s engine, OkHttp 300s read/write, per-request 300s Ktor) = **300s** = 5 min, matches user report

Target ceiling: 600_000 ms / 600.0 s = 10 min across all layers. Connect timeout (30s) stays as-is — TCP handshake is fast; only the post-handshake stream needs the longer window.
</background>
