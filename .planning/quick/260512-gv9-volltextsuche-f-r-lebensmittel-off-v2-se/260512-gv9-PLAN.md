<objective>
Upgrade the OpenFoodFacts full-text food search from the legacy `cgi/search.pl` endpoint to the modern `/api/v2/search` (with relevance sort + German preference + brand field), and close the iOS UI gap so remote search results actually render in `NutritionFoodEntryView` with the same flow Android already has. Then close the visual divergence by rendering the new brand field on Android's existing `RemoteFoodCard` too.

Purpose: The current legacy endpoint returns poor matches and no brand info. iOS users currently get no remote search rendering at all -- the ViewModel produces state that nobody draws. Android already renders results but would silently ignore the new `brand` field if it weren't wired into `RemoteFoodCard`.

Output:
- `shared/` API + DTO + use case migrated to v2, brand surfaced through the domain layer.
- iOS view renders header, progress, error, empty state, and tappable result cards consistent with the existing `foodRow` style.
- Android `RemoteFoodCard` shows the brand next to the product name when present, so iOS and Android stay visually aligned.
- Three atomic commits, single-platform each (shared backend; iOS UI; Android UI brand).
</objective>
