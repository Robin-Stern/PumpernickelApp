<objective>
Registriere die OAuth-Redirect-URI auf System-Ebene auf beiden Plattformen, damit die in Plan 05 implementierte `OAuthBrowserLauncher` zur Laufzeit funktional ist.

Purpose: Browser-Redirect zur App-Internal-URL fangen. Auf Android via `<intent-filter>` auf MainActivity + `onNewIntent`-Override. Auf iOS via `CFBundleURLTypes` in Info.plist — `ASWebAuthenticationSession` matched intern, kein zusätzlicher App-Delegate-Hook nötig (Apple's framework liefert die callback-URL direkt im completion handler, das System-URL-Routing-via-AppDelegate-openURL ist umgegangen). Die `CFBundleURLTypes`-Registration ist trotzdem nötig damit iOS überhaupt weiß dass diese URL "uns gehört" — sonst öffnet das System die URL im Safari Browser.

Output: 2 Native-Manifest-Files + 2 Native-Bootstrap-Files.
</objective>

    /**
     * Phase 22 (D-22-01) — Chrome CustomTabs redirect intercept. The
     * `<intent-filter>` registered on this activity catches
     * `pumpernickel-oauth://callback?code=...` URLs; with launchMode=singleTop,
     * Android delivers them here instead of starting a new activity.
     *
     * Defensive: only handle intents whose data scheme matches; everything else
     * is forwarded to super so platform features (deep links etc.) keep
     * working. Today there are no other deep-link consumers — this is just
     * future-proofing.
     */
    override fun onNewIntent(intent: Intent) {
        super.onNewIntent(intent)
        if (intent.data?.scheme == "pumpernickel-oauth") {
            OAuthBrowserLauncherHost.handleRedirect(intent)
        }
        setIntent(intent)  // so subsequent getIntent() reads see the latest
    }

Hinweis:
- `CFBundleURLName` ist eine app-eindeutige String-ID; per Apple-Konvention verwenden wir reverse-DNS
- `CFBundleTypeRole = None` weil wir die URLs nicht selber öffnen-müssen — `ASWebAuthenticationSession` liest die Redirect-URL aus dem in-app Browser-Sheet direkt; iOS gibt sie NICHT an `AppDelegate.application(_:open:options:)` weiter (siehe Apple-Doku zu `ASWebAuthenticationSession`)
- Konsequenz: KEINE Änderung an AppDelegate.swift oder PumpernickelApp.swift nötig — wenn das `prefersEphemeralWebBrowserSession = true` in Plan 05 wirkt, leitet das System die Redirect-URL ausschließlich an den completion handler weiter
