- **Smell 14 (`ApiKeyState`-Global) wird HIER nicht gefixt:** `SettingsRepository` selbst nutzt `ApiKeyState.set(...)` — diese Aufrufe bleiben drin. D-20-01 setzt Smell 14 out-of-scope.
- **Koin bind-Syntax:** Multi-bind-Chain in Koin 4.2.0: `single { ... } bind X::class bind Y::class bind Z::class` — geltend laut Status-quo `SharedModule.kt:94`. Drei Bindings hintereinander funktioniert sauber.
- **EarlyExitBudgetStore-Method-Signaturen passen nicht zu EarlyExitTracker-Aufrufen:** Falls in Plan 20-01 die Methodensignaturen nicht exakt dem Status-quo-Code in EarlyExitTracker entsprechen → kommt heraus beim Compile in Task 2. - **KMP-NativeCoroutines:** SettingsRepository wird in KoinHelper(s) **nicht** direkt exposed (nur ViewModels werden's). Niedriges Swift-Risiko. ABER: einige Swift-Files (z.B. SettingsView.swift) könnten via VM die Flows auf SettingsRepository (z.B. `weightUnitFlow: StateFlow<WeightUnit>`) konsumieren — Property-Namen-Stabilität ist hier wichtig. Test in Plan 20-13.
- **Atomic commit:** Großer Commit (12 Files), aber semantisch ein-Ding: "Settings-Abstraktion einziehen".
