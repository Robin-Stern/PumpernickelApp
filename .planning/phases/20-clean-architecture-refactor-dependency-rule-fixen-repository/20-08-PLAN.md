# Plan 20-08: GamificationEngine + NutritionGoalDayPolicy aus data.db entkoppeln (Smell 3 + D-20-07)

<objective>
Smell 3: `domain/gamification/GamificationEngine.kt` importiert `data.db.{CompletedWorkoutDao, ExerciseDao, NutritionDao}` + `data.repository.{GamificationRepository, SettingsRepository}`. `domain/gamification/NutritionGoalDayPolicy.kt` importiert `data.db.ConsumptionEntryEntity` in der Funktionssignatur — ein Pure-Predicate hängt am Room-Schema.

Fix:
- **GamificationEngine:** Konstruktor-Params auf Repository-Abstraktionen umstellen. DAOs raus. - **Test:** `NutritionGoalDayPolicyTest` von Entity-Konstruktion auf `ConsumptionEntry.fromFood(...)` oder direktes `ConsumptionEntry(...)`-Konstruktor umbauen.
- **Callsites:** `RetroactiveWalker` (und falls relevant `GamificationEngine.processWorkout` / `GoalDayTrigger`) mappen Entity → Domain VOR dem Aufruf.

Purpose: Domain-Layer ist nach diesem Plan frei von Room-Imports in den zwei Hotspot-Files (Smell 3 abgeschlossen).

Output: 2 Domain-Files cleansed, 1 Test angepasst, 1–2 Adapter-Callsites geupdated, 1 Koin-Modul-File ggf. angepasst falls Engine-Konstruktor-Param-Liste sich ändert.

- **Pitfall: Verhaltensänderung in Policy.** Die Summen-Math ist heute auf Entity per `it.caloriesPer100 / 100.0 * it.amount`.
