- **Permission-Settings-Deep-Link Button:** Standard Material/HIG-Touch-Target (`44pt` iOS / `48dp` Android).

## Color

Phase 19 nutzt **ausschließlich semantische Tokens** des bestehenden Theme-Systems. Keine Hardcoded-Hex-Werte. Dies stellt sicher, dass die geofence-UI mit allen 8 Accent-Presets und Light/Dark-Mode funktioniert.

| Role | iOS Token | Android Token | Phase-19-Verwendung |
|------|-----------|---------------|---------------------|
| Dominant (60%) — Background | `Color(.systemBackground)` / `Color(.systemGroupedBackground)` | `MaterialTheme.colorScheme.background` / `surface` | Rationale-Sheet Hintergrund; Detail-Sheet Hintergrund; WorkoutSessionView Hintergrund (bereits gesetzt) |
| Secondary (30%) — Container/Card | `Color(.secondarySystemGroupedBackground)` | `MaterialTheme.colorScheme.surfaceVariant.copy(alpha = 0.6f)` (analog `NutritionGoalsBanner`) | Status-Chip Background im Inactive-State; Permission-Banner Background; Settings-Row Background |

| Warning | iOS: `.orange` (System) | Android: `MaterialTheme.colorScheme.tertiary` (mapped to Material orange-warm, siehe `Theme.kt:36-39 tertiary=0xFFFF9800`) | Status-Chip „Grace m:ss" Fill; Permission-Banner („When-In-Use only") Akzent-Icon |

- Primary-CTA Buttons in Sheets („Aktivieren" im Rationale-Sheet; „In Einstellungen ändern" im Detail-Sheet)

**Accent NICHT verwendet für:**
- Permission-Banner (orange/warning oder neutral, nie accent — Accent suggests „funktioniert", Banner kommuniziert das Gegenteil)
- Status-Chip-Background im Grace/Exited/Inactive State
- Notification-Body (System-Default, kein Custom-Branding)

## Layout & Interaction Contracts

### Status-Chip Placement (D-19-16)

**iOS:** `ToolbarItem(placement: .navigationBarTrailing)` — als letztes Element im Menu-Toolbar (oder als eigenes Toolbar-Item links neben `ellipsis.circle`). Falls Toolbar zu voll → unter dem Header (`headerSection` in `WorkoutSessionView.swift:310`), rechtsbündig in der ersten HStack rechts neben dem Elapsed-Timer.

**Android:** `TopAppBar` actions-slot (rechts vor dem Menu-Icon), oder im headerSection oberhalb der Übungs-Karte als chip-row.

**Verbindlich:** Chip ist auf **beiden** Plattformen während des gesamten `WorkoutSessionState.Active`-Zustands sichtbar. Im `Reviewing`/`Finished`-State verschwindet er.

### „Workout beenden"-Button Placement (D-19-08)

**iOS:** Neuer `Menu`-Item im bestehenden `ellipsis.circle`-Toolbar-Menu — direkt unter „Finish Workout" (das bestehende Item, das `enterReview()` ruft). Label: „Workout beenden" + SF Symbol `xmark.circle`. Tap-Handler löst die D-19-08-Verzweigungslogik aus.

**Android:** Neuer `DropdownMenuItem` im bestehenden `TopAppBar`-DropdownMenu. Label: „Workout beenden" + `Icons.Filled.Cancel`. Material outlined-button als zusätzliche Affordance ist **nicht** nötig (Toolbar-Item reicht — vermeidet UI-Duplikation).

**Verbindlich:** Beim Tap mit `loggedSetCount > 0 && allSetsCompleted == false` → Confirm-Dialog. Bei `allSetsCompleted == true` → direkt `enterReview()` ohne Confirm.

### Permission Banner Placement (D-19-10, D-19-11)

**Beide Plattformen:** Direkt unter dem Header, **oberhalb** der Rest-Timer / Set-Input-Section in `WorkoutSessionView` activeWorkoutView. Banner verschwindet automatisch sobald Permission auf `ALWAYS` upgraded wird (re-evaluate beim `onAppear` / `LaunchedEffect`).

### Rationale-Sheet Trigger (D-19-09)

**Fires on:** Erster Tap auf „Workout starten" pro Cold-Start, **wenn** `currentLocationStatus() != ALWAYS`. Geguarded durch `hasShownRationaleThisSession: Boolean` State in `WorkoutSessionViewModel` (kein DataStore — nicht persistieren, soll bei jedem App-Start einmal pro Workout-Try erscheinen, bis Permission erteilt ist).

**Sheet-Größe:** iOS — `.presentationDetents([.medium])` (~50% Screen). Android — `ModalBottomSheet` mit `sheetState = rememberModalBottomSheetState(skipPartiallyExpanded = false)`.

**Dismissibility:** Backdrop-Tap und Swipe-Down erlaubt — beides counted als „Später" (kein Permission-Dialog).

### Detail-Sheet Trigger (Settings → Workout Enforcement)

**iOS:** Push-Navigation via `NavigationLink` (innerhalb der Settings-NavigationStack) — kein Modal. Detail füllt den ganzen Screen.

**Android:** `ModalBottomSheet` (analog zu anderen Settings-Detail-Patterns in der App, z.B. AchievementGalleryScreen-Pattern).

### Chip State Transitions

```
Initial state on Active-Start:
  permission = ALWAYS && location-known
      → Inactive (waiting for 1st set)
  permission < ALWAYS
      → Inactive (with banner above)

After 1st set logged:
  geofenceProvider.register() success
      → In Zone

GeofenceEvent.EXIT received:
  → Exited (visible ~1s for haptic/visual ack)
  → Grace m:ss (countdown starts at 5:00)

During Grace:
  GeofenceEvent.ENTER received
      → In Zone (notification „Workout läuft weiter")
  Timer reaches 0:00
      → (chip removed, view dismisses to Finished/HistoryDetail)

Permission-State changes mid-workout (rare):
  ALWAYS → WHEN_IN_USE → banner appears, chip stays In Zone (best-effort)
  ALWAYS → DENIED → chip → Inactive, banner appears, but already-set anchor monitoring continues
```

## Accessibility Contract

| Element | iOS | Android |
|---------|-----|---------|
| Status-Chip | `.accessibilityElement(children: .ignore)` + `.accessibilityLabel("Geofence-Status: In Zone")` (dynamisch pro State) | `Modifier.semantics { contentDescription = "Geofence-Status: In Zone" }` |

- Banner Title+Subtitle dürfen jeweils auf 2 Zeilen wachsen.
